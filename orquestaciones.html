Un equipo de tres pipelines

Un pipeline es una skill que invoca otras skills en orden. Cada skill primitiva hace una sola tarea y entrega un resultado. El pipeline para una vez, en el punto donde tú decides.

Skill primitiva Pausa humana: apruebas o pides cambios Pipeline: invoca las primitivas en orden

Dos tipos de skill

Las dos son carpetas con un SKILL.md. Cambia lo que hacen: una ejecuta una tarea; la otra ordena tareas.

verbo-objeto

Skill primitiva

Hace una tarea y entrega un resultado que puedes revisar.

  • Una tarea en cada skill.
  • Se puede usar sola: /define-test S1.
  • Su resultado es la entrada de la siguiente.
define-test→.feature
objeto-rol

Pipeline

Invoca las skills primitivas en orden y para cuando hace falta tu decisión.

  • Una sola pausa en cada pipeline.
  • Empieza en una conversación nueva.
  • No añade reglas: las reglas están en las primitivas.
define-test→🧑→implement-test→fix-test

Tres reglas del reparto

El reparto es por responsable: uno construye, otro prueba y otro juzga.

1

Una pausa por pipeline

El pipeline para donde se decide algo: la spec, los escenarios o el veredicto. Otra pausa solo repetiría la aprobación.

2

Una conversación nueva

Cada pipeline empieza sin el contexto del anterior, como otra persona del equipo. No hereda supuestos.

3

Nadie se juzga a sí mismo

El contexto que escribe el código no escribe sus pruebas. El contexto que escribe las pruebas no decide el veredicto.

Las skills primitivas hacen el trabajo. El pipeline las ordena. Tú decides en la pausa.
